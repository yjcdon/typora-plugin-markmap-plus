# Markmap Plus 独立插件技术方案

日期：2026-10-29。状态：设计方案，接口与兼容性待实施验证。

依据：[产品方案](01-产品方案.md)。执行与验证：[任务清单](03-任务清单.md) · [测试用例](04-测试用例.md)。

## 1. 技术结论与现状

将现有 TypeScript 插件改为自包含浏览器运行包，由 Typora 页面中的专属入口加载。入口在编辑器就绪后启动插件；Windows 与 macOS 分别适配文件操作，共用导图业务实现。

2026-10-29 检查当前 `main` 分支得到以下事实：

| 位置 | 当前职责与依赖 | 改造方向 |
| --- | --- | --- |
| `src/main.ts` | 继承框架 `Plugin`，使用 `PluginSettings`；内含 `TyporaAdapter` | 分离启动编排、编辑器适配和设置存储 |
| `src/settings.ts` | 继承框架 `SettingTab` | 独立设置面板，沿用配置项与默认值 |
| `src/components/TocMindmap.ts` | 渲染、布局、正文定位和监听 | 复用业务；集中管理监听释放与切换文档行为 |
| `src/components/FloatingButton.ts` | 悬浮按钮 | 复用现有交互 |
| `src/export.ts` | 框架 `path`，Typora `File`、`bridge`、`reqnode` | 平台适配收口，保留导出规则 |
| `rollup.config.js`、`build.js` | 框架虚拟模块与开发加载流程 | 改为独立打包入口与本地资源引用 |
| `src/manifest.json` | 当前版本 1.7.4，含框架最低版本字段 | 改为独立发布元数据与实测兼容记录 |
| `.github/workflows/release.yml` | 将 dist 根文件打包为 plugin.zip | 输出包含 markmap-plus 根目录的独立包 |

现有导出代码已经区分 Node 文件写入与 macOS 原生桥接。现有正文监听混合使用编辑器事件与 MutationObserver，部分事件回调缺少显式释放引用；迁移时一起落实生命周期管理。

本机 Typora 1.12.3 的 `TypeMark/index.html` 中存在社区框架加载标签。Windows 入口路径依据社区框架安装文档，待 Windows 实机确认：[安装文档](https://github.com/typora-community-plugin/typora-community-plugin/blob/main/docs/zh-cn/user-guide/1a-installation.md)。

## 2. 交付结构与职责

```text
markmap-plus/
├── INSTALL.md          AI 安装、更新、卸载契约
├── manifest.json       包标识、版本与兼容记录
├── loader.js           插件加载与就绪控制
├── app/                主程序、CSS、字体和本地渲染资源
└── data/
    └── settings.json   首次运行或迁移时生成
```

程序通过自身脚本 URL 确定资源根路径。用户配置由安装时确定的平台目录定位，文档路径仅用于正文资源和导出。

| 模块 | 职责与状态所有权 |
| --- | --- |
| 专属入口 | 加载 loader.js，处理插件目录缺失这一停用场景 |
| loader | 当前窗口唯一实例、就绪等待、启动失败与释放 |
| 编辑器适配 | Markdown、标题/正文块、当前文件、图片路径、文档变化通知 |
| 平台适配 | 路径处理、文件读取、原子写入、目录检查、移到废纸篓 |
| 设置模块 | 配置结构版本、默认值、已保存值、当前编辑草稿 |
| 导图组件 | 当前文档节点、展开状态、视图、尺寸与挂载位置 |

代码目录可沿用现有 components，新增 bootstrap、adapter、settings 职责文件。划分以实际调用关系为准。

## 4. AI 安装契约

目标目录：Windows 为 `%APPDATA%\Typora\markmap-plus`；macOS 为 `~/Library/Application Support/abnerworks.Typora/markmap-plus`。Windows 使用当前安装程序实际支持的用户数据协议访问资源；macOS 使用正确编码的 file URL。两端 URL 可读性是先行验证项。

INSTALL.md 描述以下确定流程，并给出经实测的入口模板：

1. 读取包版本、系统、架构、Typora 版本与实际应用路径，检查目标页面结构和写入权限。
2. 引导用户保存文档、退出 Typora，记录操作前入口与程序状态。
3. 在明确位置保存本次修改前的页面和程序备份，记录 Typora 版本；将完整程序放入目标目录，沿用 data。
4. 使用 `MARKMAP_PLUS_START` 和 `MARKMAP_PLUS_END` 注释标记专属入口。已有完整标记时替换该段；首次安装插入结束 body 前。标记异常时报告实际内容供修复。
5. 首次迁移读取旧配置并写入独立设置，完成后精确停用旧 Markmap。其他框架插件沿用原配置。
6. 复核单个入口、URL 编码、文件存在性、配置读回与备份位置；报告“文件配置完成”，运行结果由重启后的验证确认。

更新替换 loader、app、manifest 和说明，保留 data。更新失败恢复本次操作前的相应文件。Typora 升级后基于新页面重建标记段；完整卸载也只清理当前页面的标记段，避免用旧版本整页覆盖新页面。废弃文件统一移到废纸篓。

## 5. 启动与生命周期

专属入口负责加载外部脚本；文件夹缺失时执行空操作，其他加载错误留下文件位置与阶段记录。loader 使用窗口级专属实例引用实现重复加载幂等。

拟定状态：`waiting`（等待编辑器）、`starting`（初始化）、`ready`（可用）、`failed`（启动失败）、`disposed`（已释放）。正常流程为 waiting → starting → ready → disposed；等待或初始化错误进入 failed，并释放已创建资源。

就绪条件包括正文容器和已确认的编辑器接口。优先采用实测的就绪通知；缺少适用通知的版本采用最长 15 秒、每 100 毫秒一次的有界检查。该参数为初始设计值，按冷启动实测调整。超时后停止检查，记录缺失能力并提示当前版本与失败阶段。

正文变化采用经验证的事件订阅；正文 DOM 监听仅观察编辑区域，并过滤导图自身操作引发的变化。订阅接口返回清理函数。窗口退出或初始化失败时，统一释放事件、Observer、定时器、拖拽实例、导图 DOM 和专属样式。

切换文件后重新读取当前文档，旧节点 ID 和折叠匹配缓存按文档边界重置。同一文档编辑继续沿用现有折叠保持规则。多窗口各自持有运行状态。

## 6. 设置与平台接口

建议设置结构为 `schemaVersion`（配置结构版本，首版为 1）与 `values`（业务设置值，沿用 MarkmapSettings）。程序版本与配置结构版本分别管理。

| 接口职责 | 输入 | 输出与失败语义 |
| --- | --- | --- |
| 读取设置 | 确认的配置路径 | 文件缺失返回首次使用状态；格式损坏返回文件路径和原因 |
| 保存设置 | 经校验的设置对象 | 原子替换成功后返回；失败保留已有文件并提示原因 |
| 读取正文与块 | 当前编辑器 | Markdown、块 ID、显示文本、DOM 引用；切换时重建 |
| 订阅文档变化 | 更新回调 | 返回释放函数 |
| 保存导出 | 目标路径、字节内容 | 成功返回目标路径；失败返回平台错误 |

默认值用于首次使用及兼容新增字段；格式错误保留原文件并提示修复。旧设置搜索顺序：`util6.markmapplus`、`typora-community-plugin.markmapplus`、`typora-plugin-markmap-plus`；实际文件结构先按已安装框架验证。已有独立设置优先，迁移记录来源与结果。

面板启动时读取最新配置，保存时串行写入，采用同目录唯一临时文件加原子替换。每次提交完整配置；跨窗口以最后一次成功保存为准。其他窗口在打开面板或重启时重新读取。保存成功后当前窗口才显示成功状态。

Windows 的文件能力沿用核实后的 reqnode/fs；macOS 沿用已存在的 bridge 能力，补齐配置读取验证。路径工具替换为满足现有调用的实现；macOS 命令参数逐项引用，覆盖空格、中文、单引号。导出延续现有同名覆盖行为，提交前完成内容生成。

## 7. 构建、影响与验证

将框架虚拟模块改为独立适配入口，主程序输出浏览器可加载包。Markmap 的动态资源同样定位到本地，包含公式、代码高亮所需脚本、样式与字体；静态打包完成后检查实际网络请求。第三方依赖许可证随包保留。

迁移全部调用后清理框架运行依赖及专属构建接入，调整 build.js、release.sh 与发布流程。开发构建只产出文件，部署行为由 AI 安装说明承接。发布包采用一套共用 JS 产物和两端安装指引。

主要验证门槛：

- macOS：独立资源 URL、编辑器全局接口、原生桥接、应用资源修改后的签名与重启表现。
- Windows 10：实际入口路径、用户数据协议、Node 文件能力和受保护安装目录的权限流程。
- 两端：原框架退出加载后运行、资源离线加载、多窗口、迁移、更新、移走目录和精确卸载。

每个组合记录系统、架构、Typora 版本、插件版本和验证结果。先完成双平台最小加载及文件能力验证，再迁移完整功能。代码变更后执行 TypeScript 检查和生产构建；人工验证按测试用例记录，静态检查与实机结果分别报告。
