# Markmap Plus 独立插件技术方案

日期：2026-10-29。状态：2.0.0 当前 macOS 实测组合已完成实现与验收，Windows 适配留待后续验证。

依据：[产品方案](01-产品方案.md)。执行与验证：[任务清单](03-任务清单.md) · [测试用例](04-测试用例.md) · [验证记录](05-验证记录.md)。

## 1. 技术结论与现状

将现有 TypeScript 插件改为自包含浏览器运行包，由 Typora 页面中的专属入口加载。入口在编辑器就绪后启动插件；Windows 与 macOS 分别适配文件操作，共用导图业务实现。

2026-10-29 检查当前 `main` 分支得到以下事实：

| 位置 | 当前职责 | 实现状态 |
| --- | --- | --- |
| `src/main.ts`、`src/loader.js` | 就绪等待、独立初始化与清理 | 已由专用入口承接框架生命周期 |
| `src/settings.ts`、`src/settings-store.ts`、`src/SettingsPanel.ts` | 29 个设置字段、配置校验、串行保存、原生模态面板 | 已独立实现 |
| `src/editor-adapter.ts`、`src/typora.ts` | 正文、节点、文档身份和宿主能力访问 | 已分离适配 |
| `src/components/TocMindmap.ts` | 渲染、布局、正文定位和监听 | 已管理 Observer、防抖、计时器和文档状态 |
| `src/components/FloatingButton.ts` | 悬浮按钮 | 沿用交互并释放拖拽与样式资源 |
| `src/export.ts`、`src/platform.ts` | HTML/SVG/PNG 内容与平台读写 | 路径、原子保存、公式和图片导出已实测 |
| `build.js` | esbuild 自包含构建、字体打包、压缩包生成 | 旧 Rollup、发布脚本已回收 |
| `src/manifest.json` | 2.0.0，配置结构版本 1，目标 win32/darwin | macOS 27.2 / arm64 / Typora 1.12.3 已实测；Windows deferred 表示后续验收 |
| `.github/workflows/release.yml` | 调用生产构建并使用 plugin.zip | 压缩包根目录为 markmap-plus |

平台实现区分 Windows 的 Node 文件操作和 macOS 的原生命令桥接。正文更新统一采用只监听正文结构与文字的 MutationObserver，防抖后刷新；导图位于正文区域之外。清理流程解除 Observer、取消防抖与计时器、销毁导图和拖拽资源。

本机 macOS 27.2 / arm64 / Typora 1.12.3 已清理社区框架入口并将框架目录移到废纸篓，独立插件完成启动及部分功能实测。Windows 入口路径依据社区框架安装文档，当前已完成模拟与源码检查，宿主协议仍待实机确认：[安装文档](https://github.com/typora-community-plugin/typora-community-plugin/blob/main/docs/zh-cn/user-guide/1a-installation.md)。

## 2. 交付结构与职责

```text
markmap-plus/
├── INSTALL.md          AI 安装、更新、卸载契约
├── manifest.json       包标识、版本与兼容记录
├── loader.js           插件加载与就绪控制
├── app/                主程序、CSS、字体和本地渲染资源
├── NOTICE.md               项目原有 MIT 许可
├── THIRD-PARTY-LICENSES.md  实际打包依赖的许可证
└── data/
    └── settings.json   首次运行或迁移时生成
```

程序通过自身脚本 URL 确定资源根路径。用户配置由安装时确定的平台目录定位，文档路径仅用于正文资源和导出。

| 模块 | 职责与状态所有权 |
| --- | --- |
| 专属入口 | 加载 loader.js，处理插件目录缺失这一停用场景 |
| loader | 当前窗口唯一实例、就绪等待、启动失败与释放 |
| 编辑器适配 | Markdown、标题/正文块、当前文件、图片路径、文档变化通知 |
| 平台适配 | 路径处理、文件读取、原子写入、目录检查、移到废纸篓 |
| 设置模块 | 配置结构版本、默认值、已保存值、当前编辑草稿 |
| 导图组件 | 当前文档节点、展开状态、视图、尺寸与挂载位置 |

现有 components 承载导图业务，loader、editor-adapter、platform、settings-store 和 SettingsPanel 分别承载启动、宿主访问、文件操作、配置与界面。

## 4. AI 安装契约

目标目录：Windows 为 `%APPDATA%\Typora\markmap-plus`；macOS 为 `~/Library/Application Support/abnerworks.Typora/markmap-plus`。Windows 使用当前安装程序实际支持的用户数据协议访问资源；macOS 使用正确编码的 file URL。两端 URL 可读性是先行验证项。

INSTALL.md 描述以下操作流程。macOS 入口已实测；Windows 模板需在目标环境核验：

1. 读取包版本、系统、架构、Typora 版本与实际应用路径，检查目标页面结构和写入权限。
2. 引导用户保存文档、退出 Typora，记录操作前入口与程序状态。
3. 在明确位置保存本次修改前的页面和程序备份，记录 Typora 版本；将完整程序放入目标目录，沿用 data。
4. 使用 `MARKMAP_PLUS_START` 和 `MARKMAP_PLUS_END` 注释标记专属入口。已有完整标记时替换该段；首次安装插入结束 body 前。标记异常时报告实际内容供修复。
5. 首次迁移读取旧配置并写入独立设置，完成后精确停用旧 Markmap。其他框架插件沿用原配置。
6. 复核单个入口、URL 编码、文件存在性、配置读回与备份位置；报告“文件配置完成”，运行结果由重启后的验证确认。

更新替换 loader、app、manifest 和说明，保留 data。更新失败恢复本次操作前的相应文件。Typora 升级后基于新页面重建标记段；完整卸载也只清理当前页面的标记段，避免用旧版本整页覆盖新页面。废弃文件统一移到废纸篓。

## 5. 启动与生命周期

专属入口加载 loader.js；该文件读取失败时静默结束，覆盖移走目录停用场景。文件完整性在安装检查中验证；loader 启动后的依赖加载和初始化错误提供界面提示及错误记录。窗口级 `__markmapPlus` 引用实现重复加载幂等。

状态为 `waiting`（等待编辑器）、`starting`（初始化）、`ready`（可用）、`failed`（启动失败）、`disposed`（已释放）。正常流程为 waiting → starting → ready → disposed；等待或初始化错误进入 failed 并清理已创建资源。

就绪条件包括正文容器、getMarkdown、大纲接口、File 与 _options，最长等待 15 秒，每 100 毫秒检查一次。每项脚本或样式加载也具有 15 秒完成边界。超时后停止等待并显示错误；pagehide 取消等待与资源加载，调用实例清理函数。

正文 DOM 监听只观察 #write 的 childList、subtree 与 characterData，避免由跳转高亮属性触发刷新。关闭导图时清理监听和计时器，窗口退出或初始化失败时释放全部组件与样式。渲染请求串行处理，异步完成前核对实例和文档身份。

切换文件后重新读取当前文档，旧节点 ID 和折叠匹配缓存按文档边界重置。同一文档编辑继续沿用现有折叠保持规则。多窗口各自持有运行状态。

## 6. 设置与平台接口

2.0.1 的导出目录以只读路径和“选择文件夹”按钮横向展示。`chooseExportDirectory` 在 macOS 调用 `path.selectFolderOrFile`（`dir: true`），Node 宿主调用 `dialog.showOpenDialog`（`openDirectory`）；成功返回校验后的绝对路径，取消返回 null，异常结果报错。等待期间禁用选择和保存，关闭面板后忽略旧回调。选择仅修改草稿，保存后生效。未配置目录时，界面和导出统一使用用户 Downloads 目录。

设置结构为 `schemaVersion`（配置结构版本，首版为 1）与 `values`（业务设置值，沿用 MarkmapSettings）。程序版本与配置结构版本分别管理。

| 接口职责 | 输入 | 输出与失败语义 |
| --- | --- | --- |
| 读取设置 | 确认的配置路径 | 文件缺失返回首次使用状态；格式损坏返回文件路径和原因 |
| 保存设置 | 经校验的设置对象 | 原子替换成功后返回；失败保留已有文件并提示原因 |
| 读取正文与块 | 当前编辑器 | Markdown、块 ID、显示文本、DOM 引用；切换时重建 |
| 观察正文变化 | 当前正文容器 | Observer 由组件持有并在关闭时解除 |
| 保存导出 | 目标路径、字节内容 | 成功返回目标路径；失败返回平台错误 |

默认值用于首次使用及兼容新增字段；格式错误保留原文件并提示修复。AI 按 INSTALL.md 搜索 `util6.markmapplus`、`typora-community-plugin.markmapplus`、`typora-plugin-markmap-plus`，从旧版 `{version, settings}` 中提取 settings 写入新结构。已有独立设置优先，AI 记录迁移来源与结果。

面板启动时读取最新配置，保存时串行写入，采用同目录唯一临时文件加原子替换。每次提交完整配置；跨窗口以最后一次成功保存为准。其他窗口在打开面板或重启时重新读取。保存成功后当前窗口才显示成功状态。

Windows 分支使用 reqnode/fs，失败临时文件通过 JSBridge.invoke('shell.trashItem') 回收；macOS 使用 controller.runCommand，30 秒等待上限，临时文件通过 library.trashItem 回收。设置目录来自 _options.userDataPath；macOS 命令参数逐项引用。Windows 分支已有模拟证据，实际桥接清理与权限流程仍需实测。导出延续同名覆盖行为，提交前完成内容生成。

## 7. 构建、影响与验证

esbuild 输出浏览器 IIFE 程序，由 loader 加载。markmap-lib 使用包含公式和高亮实现的入口；KaTeX 样式及全部字体位于 app，加载器先加载样式再启动主程序。导出样式构建时将字体转为 data URL，HTML 内嵌渲染器和样式，SVG/PNG 路径复用内嵌资源与图片转换。macOS 导图及对应导出采用原生 MathML 样式处理公式布局，独立 HTML 同步配置公式显示。已核对 60 个本地字体引用，完整离线交互仍需按用例覆盖。第三方依赖许可证随包保留。

许可证收集使用 esbuild 最终产物的实际输入，覆盖传递依赖；项目原有 MIT 许可由 `src/NOTICE.md` 随包提供。

构建与运行依赖已迁移到独立实现，Typora 类型包仅用于开发类型检查。构建命令为 `pnpm build` 与 `pnpm build:prod`，类型检查为 `pnpm check`；生产构建生成 dist/markmap-plus 与 plugin.zip，旧产物先移到系统废纸篓。开发构建只生成文件，安装由 AI 按 INSTALL.md 执行。两端共用 JS 产物。

主要验证门槛：

- macOS：独立资源 URL、编辑器全局接口、原生桥接、应用资源修改后的签名与重启表现。
- Windows 10：实际入口路径、用户数据协议、Node 文件能力和受保护安装目录的权限流程。
- 两端：原框架退出加载后运行、资源离线加载、多窗口、迁移、更新、移走目录和精确卸载。

每个组合记录系统、架构、Typora 版本、插件版本和验证结果。本次已完成当前 macOS 组合；后续平台先验证最小加载及文件能力，再执行完整功能回归。代码变更后执行 TypeScript 检查和生产构建；人工验证按测试用例记录，静态检查与实机结果分别报告。
